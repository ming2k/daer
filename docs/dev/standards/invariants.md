# Invariant & Constraint Governance

This document codifies the definition, categorization, and lifecycle of system invariants in `daer`. It establishes a strict policy against pseudo-invariant tag proliferation, ensuring that invariants remain high-value architectural anchors rather than ceremonial comments.

---

## 1. Core Principle: Mechanisms Over Exhortations

In software engineering, an invariant is a condition that must unconditionally hold across all valid states of a system.

**The Golden Rule**:
> **If a rule has neither a compiler-level proof nor an automated test assertion, it is NOT an invariant — it is merely an aspiration.**

---

## 2. Constraint Admissibility Matrix

Every architectural and operational rule maps deterministically into one of four categories:

| Category | Definition & Scope | Identifier Policy | Mandatory Enforcement Mechanism |
| :--- | :--- | :--- | :--- |
| **System Invariant** | Non-negotiable structural red-lines with cross-boundary blast radius (e.g. routing loop evasion, kernel/userspace policy parity, atomic epoch switching). Max ~15 across the repo. | Formally ratified in ADRs (`[INV-*]`) | 1. Package dependency firewalls<br>2. Dedicated regression test suite<br>3. Automated verification test (`daer-config::tests::config_keys`) |
| **Domain Contract** | State-machine transitions and behavioral rules within a single crate or subsystem (e.g. dialer selection policies, DNS cache TTL expiration). | **NO global `INV-` tag**.<br>Expressed as named types. | 1. Typed `enum` variants & private field encapsulation<br>2. RAII Guard patterns<br>3. Unit tests |
| **Design Specification** | Configuration file defaults, timeout constants, port presets. | **NO `INV-` tag**.<br>Expressed as design constants. | 1. Constant definitions<br>2. Schema validation tests |
| **Implementation Note** | Workarounds for platform quirks, kernel version branches, localized edge-case guards. | **NO `INV-` tag**.<br>Standard code comments. | Direct regression unit test |

---

## 3. The 3-Condition Gate for System Invariants

A rule may be elevated to a **System Invariant** if and only if it satisfies all three criteria:

1. **High Blast Radius**: Violation results in infinite packet loops, kernel panic/rejection, silent proxy bypass, or generation corruption.
2. **Durable Architecture**: It represents a foundational pillar that will not become obsolete due to routine feature iterations.
3. **Mechanically Enforced**: It specifies an automated enforcement mechanism (compiler type check, dependency firewall, or deterministic automated test).

## 4. Ratified System Invariants for daer

| Invariant ID | Title & Red-Line | Ratified ADR | Enforcement Mechanism |
| :--- | :--- | :--- | :--- |

| **`[INV-LOADER-01]`** | **Single Config Loader SSOT**: Diagnostics and daemon must resolve and lower configuration identically. | [ADR-0006](../../adr/0006-wiring-ownership.md) | Single shared function `daer_control::load_resolved`; tested in `crates/daer-control/tests/router.rs`. |
| **`[INV-KERNEL-01]`** | **Kernel Policy Fidelity**: Kernel eBPF routing policy is provably equivalent to userspace or explicitly defers. | [ADR-0005](../../adr/0005-kernel-policy-encoding.md) | `KernelPolicy::verify_equivalence`, tests in `crates/daer-routing/tests/kernel_policy.rs`. |
| **`[INV-EPOCH-01]`** | **Dual-Slot Epoch Handover**: Datapath reload writes the inactive slot fully before atomic integer switch. | [ADR-0004](../../adr/0004-routing-epochs.md) | Dual-slot map layout in `daer-ebpf`, verified in `crates/daer-control/tests/handover.rs`. |
| **`[INV-NETUNE-01]`** | **Netune Capability Boundary**: Outbound client stack lives in `netune`; transparent proxy appliance lives in `daer`. | [ADR-0002](../../adr/0002-netune-boundary.md), [ADR-0010](../../adr/0010-reality-client-ownership.md), [ADR-0017](../../adr/0017-proxy-protocols-crate-boundary.md) | Cargo dependency pinning, crate isolation audits. |
| **`[INV-RELAY-01]`** | **Data Path Stays Stable**: `daer-relay` decides nothing. It does not depend on `daer-config`, `daer-outbound`, `daer-routing` or `daer-proxy-protocols`, and its seam (`Decide`, `DatagramRouter`) names no routing concept. The TCP accept loop never awaits a routing decision or a dial, and the datagram relay is an independent task. | [ADR-0018](../../adr/0018-userspace-data-path-is-daer-relay.md) | `crates/daer-relay/Cargo.toml` dependency closure; the doubles in `crates/daer-relay/src/testkit.rs` are what the loop's tests run against, so a routing type in the seam breaks the build. `serve::tests::a_slow_decision_does_not_block_accepting_the_next_flow` is the liveness falsifier. |
| **`[INV-PROTO-01]`** | **Proxy Protocols Are Not Re-Exported**: `daer-outbound` owns outbound governance and does not re-export `daer-proxy-protocols` types, so no protocol handshake is reachable through the governance crate's surface. | [ADR-0017](../../adr/0017-proxy-protocols-crate-boundary.md) | `daer-outbound`'s dependency closure contains no `quinn`, `h3`, `rustls`, `x25519-dalek`, `ml-kem` or AEAD crate; `crates/daer-outbound/src/lib.rs` re-exports only `fragment`. |
| **`[INV-VERIFY-01]`** | **Falsifiable Verification**: Every datapath claim must name its falsifier and include negative controls. | [ADR-0007](../../adr/0007-verification.md) | Dynamic per-run nonces and negative bypass control in `tests/transparent.rs`. |
| **`[INV-DATAPATH-ABI-01]`** | **The Loader Loads, It Does Not Repair**: the object `cargo xtask ebpf` builds loads through `aya` with no post-processing. Section names, map names and program names are daer's, spelled the way `aya` parses them; there is no load-time ELF or BTF rewrite. | [ADR-0020](../../adr/0020-datapath-is-daer-own.md) | (1) `crates/daer-ebpf/tests/object.rs::every_program_section_is_one_aya_parses` — `Object::parse` rejects `tc/<name>`, so a section needing repair cannot parse. (2) `every_program_keeps_a_verifier_legal_func_info_after_linking` reproduces `aya`'s `relocate_calls` with the same `text_sections` set and asserts every program's first `func_info.insn_off == 0`, the invariant `check_btf_func()` enforces. (3) `crates/daer-ebpf/src/elf.rs` does not exist, so there is nowhere for a rewrite to be added back silently. |
| **`[INV-ABI-01]`** | **One Source For The Kernel ABI**: map names, program names, discriminants and struct layouts are declared once in `ebpf/abi.toml` and generated into both the C header and the Rust crate. No hand-written copy exists on either side. | [ADR-0021](../../adr/0021-kernel-abi-single-source.md) | (1) `cargo xtask abi --check`, run as the first step of `cargo xtask ci`, regenerates in memory and exits non-zero on any byte difference in `daer_abi.h`, `daer_abi_assertions.h` or `generated.rs`. (2) The generated C header emits `_Static_assert` for every struct size, alignment and field offset, so a layout declared in `abi.toml` that disagrees with `tproxy.c` fails to compile. (3) `abi::Abi::validate` rejects duplicate names, a section prefix `aya` cannot parse, and a field offset that overruns its struct. |
| **`[INV-DATAPATH-MOD-01]`** | **One Module Owns One Map Set**: a datapath module writes only the maps it owns, and `datapath.c` (the translation unit) contains no logic. The cut lines are map ownership and attach domain, not directory convention. | [ADR-0028](../../adr/0024-datapath-source-layout.md) | (1) The ownership table in ADR-0028 is the specification; `ebpf/kern/src/*.h` map declarations are the enforcement, because a module that writes another's map has to reach for a declaration that is not in its dependency closure. (2) `ebpf/kern/tproxy.c` is an include list plus the licence string — its length is the smell detector, and `cargo xtask ebpf` compiling the same `.text` size before and after any split is what proves the split did not perturb code generation. |
| **`[INV-PREFLIGHT-01]`** | **A Dry Run Changes Nothing, and the Unprivileged Gate Names Its Own Boundary**: `daer check` and `daer run --dry-run` perform no `bind()`, create no device, write no sysctl, install no route and make no `bpf()` call. A check that needs a capability is not part of that gate — it is the privileged gate's job. | [ADR-0029](../../adr/0025-verification-at-the-privilege-boundary.md) | (1) Structural: `--dry-run` returns before the first mutating call, and the preflight module names none of `PreparedIngress::prepare`, `Daemon::bind_in`, `Sysctl::apply`, `RouteTable::install` or `datapath::attach`. (2) Observed: `strace -e trace=bind,bpf` over a dry run records zero calls. (3) `daer check --object` exits non-zero on an object whose first `func_info.insn_off != 0`, reproducing the `nonzero insn_off 3` production failure unprivileged. |
| **`[INV-WIRING-01]`** | **Zero Unconsumed Configuration**: Every accepted config key must be read by daemon or rejected by schema. | [ADR-0006](../../adr/0006-wiring-ownership.md) | `daer-config::tests::config_keys` in test suite. |
| **`[INV-PARTITION-01]`** | **Partitioned Policy Invariance**: Prefix L4/IP rules compiled into eBPF before the deferral gate are provably equivalent to userspace evaluation. | [ADR-0011](../../adr/0011-partitioned-kernel-routing.md) | Verified in `daer-routing::kernel::compile` and `daer-routing/tests/kernel_policy.rs`. |
| **`[INV-FAKEIP-01]`** | **Fake-IP Isolation Guarantee**: When `[dns.fake-ip]` is disabled, synthetic addresses are never allocated and `198.18.0.0/15` produces zero reverse mappings. | [ADR-0012](../../adr/0012-optional-fake-ip-ebpf.md) | Enforced via `FakeIpPool`'s typestate and its unit tests in `daer-dns/src/fake_ip.rs`; the end-to-end behaviour is `daer-dns/tests/end_to_end.rs::fake_ip_*`. |
| **`[INV-DATAPATH-01]`** | **Datapath State Ownership**: Attaching the datapath installs every piece of state it needs in the namespace that owns it — the ingress-interface rule and `local default` route for v4 and v6 in `daer0ns`, the peer and host sysctls, the link-layer variant chosen from `ARPHRD`, and all three `listen_socket_map` slots — and removes it on drop. The host keeps no mark-keyed table-2023 rule, because the listener's marked replies must leave through the peer rather than loop to `lo`. No required state is documentation-only, and no interface gets both the `_l2` and `_l3` variant of a hook. | [ADR-0013](../../adr/0013-datapath-state-ownership.md), [ADR-0038](../../adr/0038-private-ingress-network-namespace.md) | `daer-control::netns::{IngressNamespace, PreparedIngress}`, `daer-control::datapath::{attach, RouteTable, Sysctl, LinkKind}`, `daer-ebpf::listeners`; `datapath::tests::the_policy_rule_is_keyed_by_ingress_not_by_mark` is the non-privileged falsifier, and the kernel side is gated in `daer-ebpf/tests/kernel.rs`. |
| **`[INV-KERNEL-FACTS-01]`** | **Observed-Fact Honesty**: A `mac(...)`, `dscp(...)`, or `pname(...)` rule matches only when the datapath observed that fact. With no observer the fact is `KernelFacts::default()` and the rule does not match; a `pid` of `0` reports the process name as unknown rather than empty. | [ADR-0013](../../adr/0013-datapath-state-ownership.md) | `daer-control::decide::{KernelObserver, KernelFacts::from_handoff, verdict_for_flow}`; `decide::tests::a_mac_rule_*`, `a_pname_rule_*`, `a_pid_of_zero_*`. |
| **`[INV-DRB-01]`** | **Precompiled Rule Determinism**: A DRB v2 artifact encodes only merged closed intervals and one front-coded, reversed-label-sorted domain table; decoding merges no intervals and mutates no pattern, and corruption is caught by magic, version and payload SHA-256. One writer, from one intermediate form: every source is read into `daer_rule_ast::RuleSet`, so two sources naming the same rules produce **byte-identical** artifacts, and `compile(decompile(drb)) == drb`. | [ADR-0031](../../adr/0031-drb-v2-and-canonical-rules.md), [ADR-0032](../../adr/0032-flat-front-coded-domain-table.md), [ADR-0033](../../adr/0033-one-domain-table-two-vocabularies.md) | `daer-routing::drb::{DrbSet, DrbError}`; `crates/daer-routing/tests/ast_boundary.rs` (dependency closure, deterministic bytes, decompile round trip); `crates/daer-routing/tests/artifact_budget.rs` (size, miss-vs-hit cost, decode budget); `drb-sets` CI `cmp` over all published artifacts. |
| **`[INV-PROVIDER-01]`** | **Rule Provider SSOT**: All rule providers (`file` and `http`) are resolved before generation building in `load_resolved` with cached fallback, ensuring offline stability and strict parity between diagnostic commands and daemon data path. | [ADR-0014](../../adr/0014-drb-rule-binary-and-providers.md) | `daer_control::rule_provider::resolve_rule_providers`, tests in `crates/daer-cli/src/main.rs`. |

| **`[INV-PROVIDER-03]`** | **No Swap Without Change**: an unchanged provider response does not rebuild the routing generation, discard measured node latency, or restart health probes; a failed refresh keeps the running rule set. | [ADR-0037](../../adr/0037-per-provider-refresh-cadence.md) | `RefreshedProvider::requires_swap`; `unchanged_content_does_not_require_a_swap`; the `Changed` gate in `refresh_due_providers`. |
| **`[INV-CLI-01]`** | **Runtime CLI Surface**: The binary exposes exactly `run`, `check`, `route`, `probe`, `schema`, `version`. | **`[INV-RULE-TOPOLOGY-01]`** | **Disjoint Rule Topology**: Production routing topologies separate pure-IP bypass rules from domain rules, placing pure-IP sets before any domain predicates to ensure eBPF in-kernel line-rate termination without userspace deferral. | [ADR-0019](../../adr/0019-rule-asset-topology-and-lookup-mechanics.md), [ADR-0036](../../adr/0036-canonical-rule-source-v2-and-symbolic-syntax.md) | Enforced in router compiler lowering and documented in operator guides. |
