# ADR-0021 — The kernel ABI has exactly one source

- Status: accepted
- Date: 2026-11-06
- Amends: [ADR-0003](0003-datapath-abi.md) decision 7 (the generator that never existed)

## Context

The kernel/userspace boundary carries more duplicated vocabulary than any other seam in the
repository, and every copy is hand-maintained:

| Kind | C (`ebpf/kern/`) | Rust (`crates/`) |
| --- | --- | --- |
| map names | 24 `SEC(".maps")` symbols | 24 constants in `daer-ebpf/src/names.rs` |
| program names | 23 `SEC("classifier/…")` symbols | 23 constants in `daer-ebpf/src/names.rs` |
| struct layouts | `struct tuples_key`, `struct match_set`, `struct routing_result`, … | `#[repr(C)]` mirrors in `daer-ebpf/src/abi.rs` |
| discriminants | `enum MatchType` (14 variants), `OUTBOUND_*` (6 defines), `L4ProtoType`, `IpVersionType` | a doc comment quoting the C, plus `Outbound::DIRECT = 0x00` and friends |

ADR-0003 predicted this and named the fix — generate the constants from upstream's
`ebpf_sync_defs.h` — but the generator was never written, so `names.rs` and `abi.rs` have
been "placeholders" for ten months. `tests/object.rs` asserts the *names* against a compiled
object, which catches a rename. Nothing asserts the *discriminants* or the *layouts*, so a
change to `MatchType`'s variant order or to a `struct` field would compile cleanly on both
sides and fail as a misrouted packet in production — the exact failure mode ADR-0007 says a
test must be able to produce.

There is a second, subtler duplication: `ebpf_sync_defs.h` is marked
`Code generated by go run ../../scripts/gen_ebpf_sync.go; DO NOT EDIT` and guarded by
`DAE_EBPF_SYNC_DEFS_H`. The generator it names is not in this repository and the prefix is
not ours. A "do not edit" header that points at a script which does not exist is a comment,
not a mechanism.

## Decision

1. **`ebpf/abi.toml` is the single source of truth for the kernel ABI vocabulary.** It
   declares, in one machine-readable file:
   - `[params]` — the fields of the load-time parameter struct, in order, with their C and
     Rust types;
   - `[maps]` — every map name and its generationality (per-generation policy vs shared
     state, the ADR-0004 classification);
   - `[programs]` — every program name and the section kind it attaches through;
   - `[match_types]`, `[outbounds]`, `[l4_protos]`, `[ip_versions]` — the discriminants;
   - `[structs]` — the byte layout of each value that crosses the boundary, field by field,
     with offsets derived from the declared types.
2. **`cargo xtask abi` generates both sides from it.** It writes:
   - `ebpf/kern/daer_abi.h` — the C header, replacing the hand-written
     `ebpf_sync_defs.h` and the `struct daer_param` / `enum` declarations that are currently
     interleaved with the datapath logic;
   - `crates/daer-ebpf/src/generated.rs` — the Rust constants, the `RuntimeParam` field
     order, and the `#[repr(C)]` structs with their `size_of` / `align_of` / offset
     assertions.
   Both files start with a header saying they are generated and naming the command.
3. **CI fails on drift.** `cargo xtask abi --check` regenerates into a temporary directory
   and diffs against the committed files. A hand edit to either generated file, or a change
   to `abi.toml` without regenerating, is a red build. This is the mechanism ADR-0003
   promised and did not get; the check is what makes "single source" true rather than
   aspirational.
4. **`daer-ebpf` keeps no hand-written copy of any generated item.** `names.rs` becomes a
   thin re-export of the generated module so call sites do not churn; `abi.rs` keeps only
   the logic that operates on the generated types (`TuplesKey` constructors, `LpmKey`
   helpers, `MatchSet::to_bytes`) and no layout declaration of its own.
5. **Layout assertions stay, and are generated.** For every struct, the generator emits
   `const _: () = assert!(size_of::<T>() == N)` and one assertion per field offset. A change
   to a C field order that is not reflected in `abi.toml` therefore fails to compile in
   Rust, which is the earliest possible place to catch it.
6. **The `dae`/Go provenance is erased from the ABI files.** `ebpf_sync_defs.h` is deleted,
   not rewritten in place: its `MatchType`, `L4ProtoType`, `IpVersionType` and `OUTBOUND_*`
   move into the generated `daer_abi.h` under daer's guard symbol, and the "generated by
   `gen_ebpf_sync.go`" banner goes with it.

## Consequences

- One file to change when a map, program, discriminant or struct field changes. The C and
  the Rust move together or the build fails; they cannot silently disagree.
- The discriminant duplication that nothing currently tests becomes compiler-enforced. This
  is the first time `MatchType`'s numeric values are checked rather than commented.
- `abi.toml` is a new artifact to learn, but it is smaller than the two files it replaces and
  it is the only place a reviewer needs to look to see the whole kernel contract.
- Generation is a build step, and `xtask ebpf` invokes it, so the dependency is not something
  a human has to remember. The first version of this ADR claimed the invocation existed before
  it did, and the packaging build worked only because the working tree happened to hold the
  files from a previous run — a clean checkout would have failed.

  **Amended: the generated files are tracked.** The original text said the header and module
  were *not* tracked, on the reasoning that generation is a build step and a release tarball
  would regenerate them. That reasoning holds for the C side and not for the Rust side.
  `crates/daer-ebpf/src/generated.rs` is a `pub mod` of a crate that `cargo test --workspace`
  compiles, and nothing generates it before `rustc` runs: the `abi` step lives in `xtask`, not
  in a `build.rs`, and adding one would make every `cargo build` shell out to a formatting
  tool. Untracked, a fresh clone, a `git archive` tarball, the crates.io view and CI's `test`
  job all fail with `E0583: file not found for module 'generated'` — the whole workspace does
  not build. It was tracked-by-accident in the working tree the checks ran in, which is
  exactly the failure mode the paragraph above describes, one layer down.

  Both generated files are now committed, and `.gitignore` does not hide them. They stay
  derived rather than authoritative: `cargo xtask abi --check` is a CI step in the `test` job
  (it was reachable only through `cargo xtask ci`, which CI does not run — so the drift gate
  ADR-0021 promises was never enforced on a pull request). A hand edit is still a red build;
  the difference is that the *absence* of the file is too.
- The generated Rust structs are `#[repr(C)]` with the same field order as the C, so
  `unsafe` reads of map values remain valid; the per-field offset assertions are what make
  that a checked claim.
